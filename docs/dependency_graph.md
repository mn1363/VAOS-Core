# VAOS Phase 1 — Dependency Graph

Generated by an AST walk of every `import`/`from ... import` statement in
`src/core/*.py` (not hand-drawn) — see the methodology note at the bottom
for how to reproduce it.

## Intra-core module graph

```
constants.py    (no imports)
exceptions.py   (no imports)
protocols.py    (no imports)
        |
        v
utils.py        -> constants, exceptions
        |
        v
config.py       -> constants, exceptions, utils
logging.py      -> constants, exceptions, utils
```

`config.py` and `logging.py` are siblings: neither imports the other. Each
independently loads its own YAML file (`configs/config.yaml` and
`configs/logging.yaml` respectively), which is what lets configuration load
before logging is configured during bootstrap, matching the intended
bootstrap order (load config → configure logging → everything else).

## Raw edge list

| Module | Imports (within `core`) |
|---|---|
| `__init__` | — |
| `constants` | — |
| `exceptions` | — |
| `protocols` | — |
| `utils` | `constants`, `exceptions` |
| `config` | `constants`, `exceptions`, `utils` |
| `logging` | `constants`, `exceptions`, `utils` |

All intra-package imports are **relative** (`from .constants import ...`),
not absolute — this is deliberate: it keeps every reference correct
regardless of whether the package is reached as `src.core` (its frozen,
installed path) or via any alternate `sys.path` setup, without hardcoding
the `src.` prefix into every file.

## Package-boundary check

Every import statement in every file under `src/core/` was checked against
the full set of other frozen top-level packages (`domain`, `application`,
`infrastructure`, `collectors`, `analyzers`, `extractors`, `scorers`,
`foundation`, `memory`, `repository`, `graph`, `vector`, `plugins`, `api`,
`cli`, `bootstrap`, `parsers`, `storage`, `pipeline`, `runtime`).

**Result: zero imports of any outer-layer package.** `core` has no
dependency on anything outside itself, as required — it is the innermost
layer of the Clean Architecture and every other layer is expected to depend
on it, never the reverse.

## Cycle check

A DFS-based cycle detector was run over the edge list above.

**Result: no cycles.** The graph is a clean DAG: three leaf modules
(`constants`, `exceptions`, `protocols`) feed one shared module (`utils`),
which feeds two independent modules (`config`, `logging`).

## Methodology (reproducible)

```python
import ast, os
from collections import defaultdict

root = "src/core"
files = sorted(f for f in os.listdir(root) if f.endswith(".py"))
edges = defaultdict(set)

for fname in files:
    mod = fname[:-3]
    tree = ast.parse(open(os.path.join(root, fname), encoding="utf-8").read())
    for node in ast.walk(tree):
        if isinstance(node, ast.ImportFrom) and node.level == 1 and node.module:
            edges[mod].add(node.module)
        # (a second pass also flags any import of an outer-layer package name,
        #  and a DFS over `edges` detects cycles -- see architecture_audit.md
        #  section 1 and 8 for how this same technique was used to verify
        #  the wider audit.)
```

This is the same technique used for the architecture-freeze audits at the
Foundation Analyzer / VAOS-platform level earlier in this project: compute
the graph from the actual source, don't assert it from memory.
